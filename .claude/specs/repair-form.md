# 補修依頼書の「依頼内容チェック・補修内容・状況内容・負担区分」を読んで分類精度を上げる（規模 M）

## 背景
- 分類はキーワードが含まれるかどうかだけで判定している（`js/classify.js:37-82`）。添付 xlsx は全セルをつないだ文字列（`mail.xlsxText`）で見ている
- 補修依頼書のチェックは**フォームのチェックボックス**で付けている。`js/xlsx.js` はセルの値しか読まないので、**どこにチェックが付いたかを今は取れていない**
- 利用者の設定（`msg-settings-20261125-0958.json`）では、主カテゴリが「業務の段階」から**手配先の区分**に作り変えられている（緊急・事故・例外・複合・メーカー・看板塗装・タンク油面計・電気セルフ・建物・外構・給排水・要内容確認）
  - 依頼内容のチェック項目（建物関係 / 外構関係 / 機器関係 / 油面計 / サービス機器 / セルフ機器 / 電気関係 / その他）は、この主カテゴリとほぼ 1 対 1 で対応する
  - 今の主ルールは、個々のメールの文をそのまま並べたもの（例: 「5番の上部にあるLED」）が多い。新しいメールには当たらず、最後の `r-other`（「依頼」を含む）に落ちて「要内容確認」になりやすい。精度が低い主な原因はここ
- 負担区分のチェック項目: ENEOS / 運営店 / 調査次第

## 決めたこと（ユーザー回答）
- 副カテゴリを依頼内容の 8 項目に**置き換える**。チェックがあればそれを使い、無いメールは件名・本文・補修内容・状況内容のキーワードで推定する。副の設定と副の手直しは初期化する
- 負担区分は SS 名と同じ扱いにする: 一覧の列・絞り込み・集計（負担区分別）・書き出し

## 方針
- コードの変更は汎用にする: チェックの読み取りと、ルールで使える項目の追加
- 主カテゴリはプログラムで書き換えない（利用者が作り込んでいるため）。かわりに、**今の設定にチェック項目のルールを足した設定ファイル**を作って渡し、設定画面の読み込みで入れてもらう

## 受入条件
1. フォームのチェックボックスのラベルとチェックの有無を読める。読む元は VML（`xl/drawings/vmlDrawingN.vml` の `x:ClientData ObjectType="Checkbox"`、`x:Checked`、`x:Anchor`、textbox の文字）。`xl/ctrlProps/ctrlPropN.xml` の `checked="Checked"` があればそちらを優先する
2. チェックボックスの文字が空のときは、置いてあるセル（Anchor の左上）から右へ数列のうち最初の空でないセルをラベルにする
3. 補修依頼書のシート（名前に「補修依頼」を含むシート。無ければ全シート）から `mail.form = { checked:[ラベル], repair, status, burden }` を作る
   - checked: チェックが付いたラベル（負担区分の 3 語を除く）
   - repair / status: 見出し「補修内容」「状況内容」の右隣の値。右が空なら下の行の値
   - burden: チェックが付いた ENEOS / 運営店 / 調査次第（複数なら先頭。無ければ空）
4. 分類ルールの対象に 3 つ足す（ルール画面の選択肢にも出る）
   - `formChecked` 依頼内容のチェック項目（改行区切り）
   - `formDetail` 補修内容・状況内容
   - `burden` 負担区分
5. 副カテゴリの初期設定を 8 項目にする。ルールは上から ① 各項目の「`formChecked` に含む」 ② 各項目の「件名・本文・補修内容・状況内容にキーワードを含む」。キーワードは利用者の今の副ルール・主ルールの語を 8 項目へ振り分けて作る（例: 計量機・ノズル→サービス機器、リフト・コンプレッサー・洗車機→機器関係、液面計・地下タンク→油面計、照明・LED・漏電→電気関係、POS・監視カメラ→セルフ機器、土間・グレーチング→外構関係、シャッター・トイレ→建物関係）
6. 設定を v3 にする。v2 を読んだら副（`axes.sub`）を初期値で置き換え、`manual[key].sub` を消して保存し直す。主・SS 名・SS 名の手直しには触れない。v1→v3 も通る
7. **利用者向けの設定ファイル**（`msg-settings-repair-form.json`、Downloads に出す。リポジトリには置かない）を作る。今の主ルールの並びに次を挟む
   - 例外系（対象外・返信・管轄外・緊急・事故・廃止等）の後に「`formChecked` に改行がある（2 項目以上）→ 複合案件」
   - 件名ルール（`r-*-subj`）の後、本文ルール（`r-*-any`）の前に、チェック項目 → 主カテゴリ
     建物関係→建物・建具・空調 / 外構関係→外構・土間 / 機器関係・サービス機器→メーカー直接対象 / 油面計→地下タンク・油面計・配管 / 電気関係・セルフ機器→電気・照明・セルフ機器 / その他→当てない（後のルールへ）
   - 副は 5 の初期値。`version: 3`
8. 負担区分: 一覧に列、絞り込み（ENEOS / 運営店 / 調査次第 / 不明）、集計に「負担区分別（主カテゴリ別）」（HTML 保存にも）。集計の表から一覧へ移るときは今の絞り込みを残して条件を足す
9. 詳細画面に「補修依頼書」の欄: 依頼内容（チェック）・補修内容・状況内容・負担区分
10. CSV / JSON 書き出しに「依頼内容チェック」「負担区分」
11. 実物の確認用に `tests/dump-xlsx.mjs <.msg か .xlsx>`。チェックボックス（ラベル・有無・位置）、`mail.form`、各見出し付近のセルを座標つきで表示する

## 非目標
- 主カテゴリの設定をプログラムで書き換えること（7 の設定ファイルを読み込むかは利用者が決める）
- 今の主ルールの、文をそのまま並べた語の整理（必要なら別作業）
- 負担区分・依頼内容チェックの手直し（手入力）
- .xls、ActiveX のチェックボックス、Excel の新しいセル内チェックボックス
- xlsx の表表示にチェック状態を描くこと
- `any` の中身を変えること
- 機械学習や自動の重み付け
- 本文・xlsx の中身を保存すること

## 進め方
1. `js/xlsx.js` のチェック読み取りと `tests/dump-xlsx.mjs` を作る
2. 実物 1 通で dump-xlsx を走らせてもらい、ラベルの位置・補修内容欄の位置を確かめる（ずれていたら 2・3 の取り方だけ直す）
3. fields → classify（移行含む）→ app / summary / report / export → `node build.mjs`
4. 受入 7 の設定ファイルを作る

## 検証
- `npm test` が全部通る
- `node tests/dump-xlsx.mjs <実物>` のチェックと `mail.form` が Excel の見た目と一致する
- index.html で実物フォルダを読み込み、7 の設定を読み込む前後で主カテゴリの件数を比べる。「要内容確認」が減り、根拠が「ルール（建物関係）」などチェック由来の件数が出る
- 負担区分の絞り込みの件数と集計の表の件数が一致する
- 今の設定（v2）が残ったブラウザで開くと、主の設定はそのまま、副だけ 8 項目になる
