# 添付 PDF（FAX）の OCR と、やり取りからの引き継ぎ

> **状態: 見送り（2026-11-20）**
> ユーザーの判断で OCR（PDF の文字の読み取り）は実装しない。
> HTML 内で完結させるには外部ライブラリと十数 MB の学習データが要り、精度も下がるため「非現実的」。
> Windows 標準 OCR を使う外部スクリプト案も採らない。
> 「やり取りからの引き継ぎ」（受入条件 4）は OCR と独立しているため、別途判断する。

規模: M（新しいスクリプト・ZIP 書き出し・新しいデータの流れ）

## 背景
- 添付 PDF は FAX を PDF にしたもの（中身は画像）。文字を読めないため、PDF しか付いていないメールは副カテゴリ・SS 名が「未分類 / SS 不明」になり、手で直す必要がある
- ブラウザだけで OCR すると、外部ライブラリと日本語の学習データ（数 MB〜）が必要になり、依存ゼロの方針に反する
- Windows 10/11 には日本語 OCR（Windows.Media.Ocr）と PDF 描画（Windows.Data.Pdf）が標準で入っている。ユーザーの PC（Windows 11）で、日本語 OCR・PDF 描画・Windows PowerShell 5.1・FullLanguage モードが使えることを確認済み
- ヒヤリング: やり取りからの引き継ぎは「入れる」。OCR の結果はブラウザに「保存しない」

## 流れ（ユーザーの操作）
1. ツールの「書き出し」→「OCR 用セットを書き出す」で ZIP を保存する
   - 中身: `pdf/` に PDF、`manifest.json`（PDF とメールの対応）、`ocr.bat`、`ocr-pdfs.ps1`、`はじめにお読みください.txt`
2. ZIP を展開し、`ocr.bat` をダブルクリックする → 同じフォルダに `ocr-results.json` ができる（進み具合を画面に表示）
3. ツールで「OCR 結果を読み込む」から `ocr-results.json` を選ぶ
   - .msg のフォルダに置いておけば、フォルダを読み込むたびに自動で読み込む

## 受入条件
1. **OCR 用セットの書き出し**
   - 対象は「xlsx が付いていないメールの PDF」（既定）か「PDF が付いたすべてのメール」を選べる。転送メールの中の PDF も含む
   - 元の .msg を 1 通ずつ読み直して PDF を取り出す。進み具合を表示する
   - ZIP は自前で作る（無圧縮。CRC32 あり）。Windows の「すべて展開」で開ける
2. **OCR スクリプト**（Windows PowerShell 5.1。追加インストールなし）
   - `ocr.bat` は `powershell -NoProfile -ExecutionPolicy Bypass -File ocr-pdfs.ps1` を呼ぶだけ
   - PDF の全ページを画像にして、日本語 OCR にかける。1 ページの長辺は最大 2400px 程度に拡大する（小さい FAX の文字を読みやすくする）
   - 日本語の 1 文字ごとの空白は詰める。英数字の語の間の空白は残す。語と語の間隔が大きいところはタブにする（表の列の区切りを残すため。SS 名の取り出しに使う）
   - 結果を `ocr-results.json`（UTF-8）に書く: `{ version, engine, createdAt, results: [{ key, attachment, pages, text, error }] }`
   - 1 つの PDF で失敗しても止まらず、error に理由を書いて次へ進む
   - 日本語 OCR が無い・PowerShell 7 で実行した、などの場合は分かる言葉で止まる
3. **OCR 結果の読み込み**
   - 「OCR 結果を読み込む」ボタン、またはフォルダ読み込み時に `ocr-results*.json` を自動で取り込む
   - メールとの対応は manifest の key（Message-ID か内容のハッシュ）で取る。一致しない結果の件数を表示する
   - 読み込んだ文字は、検索・主/副の分類（「件名・本文・送信者・添付」と新しい「添付 PDF の文字（OCR）」の対象）・SS 名の取り出し・CSV/JSON に使う
   - ブラウザには保存しない（画面を閉じたら消える）
4. **やり取りからの引き継ぎ**
   - 副カテゴリまたは SS 名がルールで決まらなかったメールについて、Message-ID / In-Reply-To / References でつながったメール（同じやり取り）のうち、決まっているものから引き継ぐ
   - 引き継ぐのは副カテゴリと SS 名だけ（主カテゴリ＝業務の段階はメールごとに違うため引き継がない）
   - 候補が複数あるときは、日時が一番近いメールを使う
   - 優先順: 手で付けたもの > ルール（OCR の文字を含む） > やり取りからの引き継ぎ
5. **表示**
   - 一覧: OCR の文字があるメールに「OCR」の印
   - 詳細: 分類理由に「OCR の文字から」「やり取り（件名…）から引き継ぎ」を出す。OCR の文字を折りたたみで表示し、「読み違いがあります」と添える
   - 添付の絞り込みに「OCR 済み」を足す
   - SS 設定タブの件数表示に「OCR から」「引き継ぎ」を足す
6. 使い方に OCR の手順・精度の注意・引き継ぎを追記する

## 非目標
- ブラウザの中での OCR（外部ライブラリが必要なため）
- 手書き文字の読み取り精度の改善、画像の前処理（傾き補正・ノイズ除去）
- Windows 以外（Mac など）での OCR
- OCR の結果をブラウザに保存すること
- 主カテゴリの引き継ぎ
- .msg を直接読む PowerShell スクリプト（PDF の取り出しはツール側で行う）

|---|---|
| `js/zip.js`（新規） | 無圧縮 ZIP の作成（CRC32） |

| `js/app.js` | 書き出し・読み込み・自動取り込み・表示・絞り込み・引き継ぎの呼び出し |
| `js/export.js` | CSV/JSON に OCR の文字の列 |
| `src/page.html` / `css/style.css` | ボタン・説明・印 |
| `tests/` | zip（展開して一致）、ocr（突き合わせ）、thread（引き継ぎ）、fields（OCR から SS）のテスト。文字入り FAX 風 PDF を作り、この PC で ps1 を実際に動かす |

## 検証
- `npm test`
- 文字を描いた画像の PDF（FAX 風）を作り、ZIP 書き出し → 展開 → `ocr.bat` → `ocr-results.json` → 読み込み、を通しで実行し、副カテゴリと SS 名が付くことを確かめる
- ZIP を Windows 標準の展開（Expand-Archive）で開けること
- 引き継ぎ: 返信でつながった「xlsx 付き」と「PDF のみ」のメールで、副・SS が引き継がれること
- 1000 件のサンプルで集計の件数がずれないこと（前回のリンク確認と同じ）
